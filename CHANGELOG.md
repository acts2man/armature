# Changelog

All notable changes to Armature are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed

- **Drag anywhere.** A dragged widget or element can now land between any two siblings at any depth, before the first or after the last, and inside an empty or nested container. The insertion edge follows the parent's own flow from the layout (a row's direction on the device being edited, reversed rows included, a grid's nearest cell edge) rather than guessing from the rectangles, and the outer few pixels of a container mean "beside it" among its parent's children. While dragging, the container that would receive the drop is outlined and the drag ghost names the target ("after Heading", "before Container", "into Container"). Unit tests cover rows with one child, reversed rows, grids, the outer band and the labels; Playwright covers a drop between middle siblings, left/right in a row, into an empty container, and a move that keeps the element's settings.
- **The canvas handles now look like Elementor's.** Hovering draws a thin outline (solid on a widget, dashed on a container) with the type label. The selected element gets a solid accent outline and a handle tab instead of the floating dark toolbar: a widget's is a square pencil outside its top-right corner (click to edit, drag to move; hovering it reveals parent, duplicate and delete), a container's straddles its top edge, centred, with add / grip / delete (and parent / duplicate on hover); a nested container's tab shifts right so it never sits on its parent's. Inline text editing, the resize handles and the spacing handles are unchanged. A Playwright test covers the outlines, both tabs, the nested offset and selecting at any depth.
- **The panel controls now match Elementor's rows and popovers (KIT_VERSION 2.2.0).** Every control is one row: the label on the left with the device icon right after it, the control on the right; wide controls (a textarea, spacing boxes, a picture) stack under their label. Typography, Text shadow, Text stroke, Box shadow and Border are one row each with a pencil that opens a popover of their fields (live, closing on a click outside or Esc without dropping the selection) and a globe where a global applies (site text styles on Typography, global colours on every colour). A colour is now a swatch button that opens the picker; a linked colour shows a globe on the swatch. Margin and Padding show four labelled boxes with the unit menu and the link toggle on the label line; alignment is an icon group; Width, HTML tag and the new Blend mode are dropdowns. The Text Editor's Content tab is a full rich-text editor in the panel with Visual and Code tabs (paragraph or heading, bold, italic, underline, strike, lists, link, alignment, colour, clear); Code shows the document as sanitized HTML and converts what is typed back, dropping unsupported tags with a notice; the panel and the canvas follow each other live. A container's Layout tab reads Content width (Boxed / Full), Width, Min height, Direction (icons), Justify, Align, Gap, Wrap, a new Structure group that changes the section's columns and moves what is inside into them, then Overflow and HTML tag. New style fields: **text stroke** (`-webkit-text-stroke`) and **blend mode** (`mix-blend-mode`); new Advanced fields for elements inside a grid: **column span** and **row span**. The kit's rich-text serializer keeps a site colour's reference (`data-ae-color`) and a numbered list's start. Tests: structure changes, the HTML round trip, the new CSS; Playwright: the Typography popover with device switching inside it, Esc and outside clicks, the margin link toggle and unit, the Text Editor panel and canvas in sync (Visual, toolbar, Code with dropped tags, and edits from the page), text stroke, blend mode and the Structure group with undo.
- **The builder now works like Elementor: one switching panel on the left, the website full-bleed to the right.** The right-hand inspector column, the left icon rail and the Navigator, Pages, Media and Site tabs are gone. A single ~340px panel on the left has two modes — Elements (a Widgets/Globals tab pair, a search box and the widget tiles in a two-column grid) and Edit (the selected element's Content/Style/Advanced, headed "Edit Heading", "Edit Container"… with a grid icon back to Elements; a container's first tab is Layout). Clicking anything on the page opens it in the panel; selecting another element swaps the panel instantly; Esc, the grid icon or clicking empty canvas returns to Elements. A collapse tab on the panel's right edge hides it so the canvas fills the window, remembered per user. Global colours, fonts and typography presets moved to the Globals tab (visible to agency staff and to clients at the style or builder level). The media library is now a modal opened from an image's "Media library" button (reuse, upload and alt text). The top bar follows Elementor's arrangement: a menu (Exit to dashboard, New page, Keyboard shortcuts), "+", History, undo/redo and Page settings on the left; the page name with a chevron to Page settings and the device toggle in the centre; draft status, Preview and a Publish button with a dropdown (Save draft, Save as template, View page) on the right. Page settings and History open in the left panel. A registered (hand-coded) site section selects as a whole and shows a note in its Content tab — clients "Ask your agency to make this section fully editable", staff "convert it to builder elements in the site's repo" — while its text and pictures stay editable on the page. Stage 1 (content-only) sites keep their existing layout. The full Playwright suite was updated for the new layout, with new tests for panel swapping across element types, Esc/grid returning to Elements, and collapse/restore.

### Fixed

- **The canvas sheet can no longer be scrolled out from under the overlays.** A `scrollIntoView` inside the site's frame (the kit's own, or a browser's) could also scroll the editor's overflow-hidden sheet by a few dozen pixels, so the frame and every overlay drawn above it shifted while drags and handles still measured from the sheet's top; the sheet now snaps back to zero on any scroll, and drag hit testing accounts for a scroll offset anyway.
- **An element's own settings now always beat a CSS class attached through Advanced > CSS classes (KIT_VERSION 2.1.0).** Sites converted from hand-coded sections keep their legacy classes on the element (Advanced > CSS classes); when the site's own stylesheet loaded after the kit's, a `.ae-root .legacy` rule could out-order and override a Style-tab value the person set in the builder. The CSS generator now emits every per-element rule through a doubled element class (`.ae-root .ae-<id>.ae-<id>`, specificity 0-3-0), so an element's Style, layout, spacing and Advanced values outrank any legacy class regardless of load order. A new unit test proves the element rule's specificity beats both `.promo` and `.ae-root .promo`.

- **The kit no longer changes how a registered site section renders (KIT_VERSION 2.0.1).** The kit's box-sizing reset (`.ae-root *`, `::before`, `::after`) leaked into hand-coded sections rendered inside `.ae-root`, forcing `border-box` on their elements and pseudo-elements — on Tree Test Prep it shrank a bordered `::before` arrow circle from 30px to 26px. Every kit reset and base rule now excludes `.ae-site-section` and everything inside it with a zero-specificity `:not(:where(.ae-site-section, .ae-site-section *))`, so a site section keeps the browser defaults it was written against. A new Playwright test in `examples/demo-site` (`/section-parity`) renders one section bare and through `<ArmatureSlot>` and asserts they are pixel-for-pixel identical, so builder CSS can never change a section's rendering again.

### Changed

- **The kit folder is shippable on its own.** The kit's unit tests moved from `kit/kit.test.ts` to `tests/kit/kit.test.ts`, so `kit/` now contains only files a site copies verbatim (no vitest or `examples/`/`shared/` imports). CI runs them unchanged.
- **`kit/README.md` added.** The kit folder now carries its own README: what it is, the exact install steps for a React Router SPA and for TanStack Start/SSR, registering site sections, layouts and `site-kit.json`, the catch-all route, the chrome and title markers, the SSR `import.meta.glob` guard, and how to update the kit. `docs/SITE_CONTRACT.md` and the root README now point to it.
- **The form-based page editor sends builder pages to the builder.** Opening a page that was built in the visual editor (a layout whose slug is not in the code) in the old form editor no longer shows "Page not found" or an empty form; it shows "This page is edited visually" with a button that opens it in the builder.

### Added

- **The Video widget adds Wistia and a generic embed URL (KIT_VERSION 2.1.0).** Alongside YouTube, Vimeo and a self-hosted file, a video can now be a Wistia media (`wistia.com/medias/…` or `fast.wistia.net/embed/iframe/…`) or any https embed address (a generic player iframe). Both keep the privacy-friendly click-to-load facade — nothing is requested from the host until a visitor presses play — and the facade names the source ("Plays from Wistia", "Loads when you press play"). The `video` zod schema, the kit renderer's id extraction and player-URL builder, and the editor's Source control all learn the two new options; tests cover Wistia id extraction, the generic embed passthrough, and a Playwright check that a Wistia video makes no request from the editor.

Pictures travel inside the draft as data URLs and are written to `public/assets/uploads/<page>-<hash>.<ext>` (PNG, JPEG, WebP, GIF or AVIF, 3 MB each; anything else that looks like a data URL is refused). When someone published in between, layouts merge element by element and value by value (`shared/builder/merge.ts`): separate edits both survive, the same edit made twice asks, and the dialog names each clash ("Both you and someone else changed heading "Recent builds"") with Keep mine / Keep theirs. Every rule is enforced against what is committed, not what the browser says (`shared/builder/permissions.ts`): the client's editing level, locked elements (words editable, place and design not) and agency-only widgets; no force-push; one `publishes` row per page. **Pages:** a Pages tab with the pages coded into the site and the pages built in the editor; New page (title, an address checked against every other page, blank, one of four starter pages or a saved page template), page settings (title, address, search title and description, sharing picture, hide from search engines, full canvas, hide the page title, page background), duplicate and delete. **Templates:** save a section (right-click) or a page as a template for this site or, for agency staff, every site of the agency; saved sections in the Elements panel; a searchable template library. **Media library:** the site's pictures and the ones added in this draft, where each is used, default alt text, insert on the page, uploads resized to WebP in the browser (at most 2000px and 3 MB), and a picker behind every image control. **Drafts saved to the account** (`builder_drafts`) every two seconds as well as in the browser; on opening, the newer one is offered back, so work follows the person to another device; a publish or a discard clears it. **Published versions** in the History panel: preview any recent publish on the canvas (read-only, from that commit) and restore it as an ordinary, undoable draft. **Editing levels:** agency staff choose, on the site overview, whether clients change words and pictures, also restyle (the canvas and inspector, nothing added, moved or removed; checked with the same rules as the publish), or use the full builder. A five-step builder tour on first use. Kit: `<html data-armature-canvas="full">` and `data-armature-hide-title` for page settings, with base CSS hiding `[data-armature-chrome]` and `[data-armature-page-title]`; the demo site marks its header, footer and page title. Migration `20260923000200_page_builder.sql` (`sites.editing_level`, `builder_drafts`, `builder_templates`, all with RLS) and its RLS proof: each person reads and writes only their own draft, agency staff may read and delete drafts of their sites, clients read their site's and the agency's templates and manage only their own site templates, agency-wide templates are staff-only, anonymous visitors see nothing. Tests: merge (per element, per value, moves, deletes, conflicts), permissions, uploads, publish end to end with a fake repository, the style level on coded pages, addresses, media usage, revisions, draft selection; Playwright: layouts and site settings in one publish, a named conflict resolved by choice, a new page with its settings published, duplicate and delete, a template saved and inserted with fresh ids, the media library (usage, alt text, insert, upload, picker), editing levels from the overview and in the editor, a draft followed to a second browser, previewing and restoring a published version, and the tour. Screenshots of the builder in `docs/screenshots/builder-*.png`. Polish: a shortcut pressed straight after clicking an element on the page now always acts on that element (the selection is committed before the next message from the page); picture previews in the inspector load from the live site; the idle inspector speaks of the Navigator when the builder is on; the Elements, Navigator, Pages, Media and Site tabs fit the panel.

- **Choose your password** on first sign-in: an account the agency created must replace the temporary password before it can open any other screen. The new password follows the same rules (at least 10 characters; not the word "password", the email address, or one character repeated).
- Two edge functions: `client-create` (agency staff only; creates the confirmed account with the service role and never returns or logs the password) and `password-set` (the signed-in person sets their own password and the must-change flag is cleared).

### Fixed

- "Add a site" / "Check connection": the step "The App can write to the repository" now passes when the installation token GitHub issued carries Contents: write. It used to read `permissions.push` from the repository response, which GitHub does not report reliably for App installation tokens, so the step failed on real deploys right after the token step had passed.
